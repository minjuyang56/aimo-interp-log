# 판정에 쓸 수 있는 정보 전체

`are_robust(model_id, problems)`가 호출된 시점에 손에 쥘 수 있는 것들.
네 층으로 나뉘고, 층마다 제약이 다르다.

관련: [컬럼 15개 해설](DATA.md)

---

## 층 1 — 함수 인자로 직접 받는 것

**두 개뿐이다.**

```python
def are_robust(model_id: str, problems: list[str]) -> list[bool]:
    #            ↑ 판정 대상 모델    ↑ 원본 문제 텍스트들
```

| 받는 것 | 예시 | 정보량 |
|---|---|---|
| `model_id` | `"gpt-5.2-2025-12-11:low"` | 문자열 하나. 어떤 모델을 판정하는지 |
| `problems` | `["Triangle ABC has...", ...]` | 원본 문제 전문. **변형본은 안 줌** |

`components/ingestion_program/ingestion.py:158-160`이 `original_problem`만 뽑아 넘긴다.
나머지 13개 컬럼은 넘어오지 않는다.

### 놓치기 쉬운 것: 배치 단위로 호출된다

채점기는 케이스를 `model_id`별로 묶어서 **그룹당 한 번** 호출한다
(`ingestion.py:146-148`). 즉 한 모델의 문제 여러 개를 **한꺼번에 본다.**

```python
are_robust("gpt-5.2:low", [문제1, 문제2, 문제3])   # 세 문제를 동시에 봄
```

그래서 배치 안에서의 **상대적 비교**가 가능하다 — "이 배치에서 이 문제가 유독 길다/짧다",
"다른 문제들에 비해 대리 모델이 유독 헤맨다" 같은 신호를 쓸 수 있다.
예제 두 개 모두 이걸 안 쓴다.

## 층 2 — 평가 컨테이너 안에서 계산할 수 있는 것

### 쓸 수 있는 모델

오프라인 HF 캐시에 **딱 하나**:

```
deepseek-ai/DeepSeek-R1-0528-Qwen3-8B
```

`HF_HOME=/app/data/huggingface`가 이미 읽기 전용으로 마운트돼 있고,
`HF_HUB_OFFLINE=1` · `TRANSFORMERS_OFFLINE=1`이 걸려 있다.
`from_pretrained(..., local_files_only=True)`로 로드한다.

**판정 대상 모델(gpt-5.2, gemini 등)은 못 돌린다.** 캐시에 없고 네트워크도 없다.
그래서 이 8B 모델은 **대리(proxy)** 로 쓰인다.

### 이 모델에서 뽑을 수 있는 신호

대회 규정 2번이 명시적으로 허용한다:

> 팀은 **가중치, 활성값, 토큰 확률, 그 밖의 모든 블랙박스 통계**를 방법의 입력으로 쓸 수 있다.

| 신호 | 얻는 법 | 비용 |
|---|---|---|
| hidden states | `output_hidden_states=True` · 전 층 × 전 토큰 위치 | 순전파 1회 |
| attention | `output_attentions=True` | 순전파 1회 |
| 로짓 · 토큰 확률 | 출력 로짓에 softmax | 순전파 1회 |
| 생성 텍스트 | `model.generate(...)` | 토큰 수만큼 |
| 토큰별 확신도 | 생성 중 `LogitsProcessor`로 가로채기 | 생성 비용 |
| 자기일관성 | 같은 문제를 여러 번 샘플링해 답 일치도 측정 | 생성 × N |
| **자체 변형 안정성** | 문제를 직접 비틀어 대리 모델에 물어보고 흔들림 측정 | 생성 × 변형본 수 |

마지막 항목이 흥미롭다. **변형본을 직접 만들어 볼 수 있다** — 주최측이 하는 일을
대리 모델로 축소 재현하는 것이다. 시간 예산 안에서만 가능하고, 예제 두 개 모두 안 한다.

### 예제 두 개가 실제로 쓰는 것

```
trained-probe          순전파 1회 → hidden_states[31] 마지막 프롬프트 토큰 → 선형 프로브
uncertainty-profiling  그리디 생성 최대 4096토큰 → 토큰별 logprob·엔트로피 → 통계 14개
```

전 층 × 전 토큰 위치 중 **한 칸만** 쓰고 있다는 뜻이다.

### 하드웨어와 시간

| | |
|---|---|
| GPU | NVIDIA RTX PRO 6000 (Blackwell) 1장 · VRAM 96GB |
| CPU / RAM | 192코어 · 메모리 상한 없음 |
| 시간 | **3600초** (예측 실행과 채점 실행에 각각 별도 적용) |
| 네트워크 | **차단** |

8B 모델 로드가 약 1분. 논문 기준 테스트셋이 약 240 인스턴스이므로,
인스턴스당 대략 **15초**가 예산이다. 생성 기반 방법은 이 안에 들어와야 한다.

## 층 3 — 제출물에 미리 넣어갈 수 있는 것

ZIP에 담아서 가져가는 모든 것. 실행 중에 만드는 게 아니라 **미리 만들어 넣는다.**

- 학습된 아티팩트 (프로브 가중치, scikit-learn 회귀모델, 임계값 등)
- `model_id`별 사전확률 룩업 테이블
- 임의의 파이썬 코드와 모듈
- 설정 파일, 상수 테이블

담으면 안 되는 것: 학습 데이터셋, 비공개 라벨, 평가 워커가 이미 제공하는 모델 가중치,
가상환경·캐시, 자격증명, 네트워크를 요구하는 코드.

**주의:** 런타임은 `Dockerfile.competition`의 패키지만 있다.
`pip install`도 `requirements.txt`도 동작하지 않는다.
아티팩트는 그 버전으로 직렬화해야 로드된다.

## 층 4 — 학습 시점에만 쓰는 것 (제출물엔 안 들어감)

### 공개 라벨 데이터

| 출처 | 규모 | 내용 |
|---|---|---|
| [`aimo-interp/val-sample`](https://huggingface.co/datasets/aimo-interp/val-sample) | **28행** | 모델 7종 × 문제 8개. 15개 컬럼 전부 |
| [`aimo-interp/baselines`](https://github.com/aimo-interp/baselines) `data/math-robust-final.csv` | **675행** | 전부 `qwen3-8b:low` · MATH 문제 · 유형별 라벨 포함 |
| 같은 저장소 `data/math-robust-agg.csv` | **141행** | 위의 `OVERALL` 집계분 |

`math-robust-final.csv`가 특히 중요하다 — **대리 모델과 같은 모델**에 대한 라벨이라
"이 모델의 내부 상태 → 이 모델의 견고성"을 직접 학습할 수 있다.

논문에 따르면 train split 150문제 × 모델 8종 ≈ **1,200 인스턴스**가 공개될 예정이다.

### 타깃으로 쓸 수 있는 컬럼

입력으로는 못 쓰지만 **정답(타깃)으로는 쓸 수 있다** — [DATA.md](DATA.md) 참고.
`absolute_accuracy_decay`가 이진 라벨보다 정보가 많다.

### 규정상 제한

> 1. 팀은 **최종 검증셋과 같은 변형 유형에 대한 추가 라벨 데이터**를 쓸 수 없다.
>    라벨 없는 데이터나 **다른 변형 유형**의 라벨 데이터는 허용된다.

즉 직접 만든 적대적 데이터로 학습하는 건 되지만, 같은 유형(rephrase, rename, domain,
distract, typos, expert_perturbations, expert_no_solution)에 대해 라벨을 새로 붙여
쓰는 건 안 된다.

## 쓸 수 없는 것 정리

| | 이유 |
|---|---|
| 판정 대상 모델 실행 | 캐시에 없음 · 네트워크 차단 |
| 실제 변형본 | 입력으로 안 넘어옴 |
| `permutation_type` | 넘어오지도 않고, **28/28 라벨 누출**이라 타깃으로도 부적절 |
| 나머지 12개 컬럼 | 실전에 존재하지 않음 (학습 타깃으로만) |
| 인터넷 · 추가 모델 다운로드 | 컨테이너 오프라인 |
| 같은 변형 유형의 추가 라벨 데이터 | 규정 1번 위반 |
