인서트 — 라벨 생성 절차 (역산 결과)

원본 문제를 10회 풀린다 → base_accuracy. 7가지 방식으로 비튼 변형본들을 풀린다 → permuted_accuracy. 둘의 차이가 absolute_accuracy_decay. 비트는 방식 5개(rephrase, rename, domain, distract, typos)는 gpt-oss-120b가 생성했고 (permutation_source 컬럼이 그 이름을 담고 있다), 2개(expert_no_solution, expert_perturbations)는 사람이 만들었다.

라벨 규칙은 논문 §1.4에 있다: 변형본 중 과반이 무너지면 False, 아니면 True. 하나만 깨져도 False가 되는 게 아니다. 그리고 애매한 케이스는 평가셋에서 아예 뺐다 ("not clear-cut"). 28건의 실제 분포가 그 증거다 — robust는 decay가 정확히 0.0, spurious는 0.5 이상, 그 사이는 텅 비어 있다. 임계값을 찾을 필요가 없다. 중간값이 존재하지 않게 만들어진 데이터다.

[author]

uncertainty-profiling이 왜 회귀모델을 쓰는지 이제 이해된다. 이진 분류가 아니라 decay를 예측하고 임계값으로 자르는 설계다. 타깃 정의를 정확히 따라간 거다. 나도 그래야 한다.

설계는 두 층이다.

1층 — 사전확률. model_id가 알려진 모델이면 평활된 기저율을, 모르는 모델이면 전체 평균을 쓴다. S#6에서 본 대로 원시 비율을 그대로 쓰면 안 된다.

2층 — 문제 신호. 대리 모델로 문제를 인코딩해 "이 문제가 표면 패턴에 의존하기 쉬운가"를 잰다. 1층의 사전확률을 이 신호로 보정한다. 

# solutions/layered/solution.py — 계약은 얇게 유지
from layered.inference import predict

def are_robust(model_id: str, problems: list[str]) -> list[bool]:

# layered/inference.py — 모델은 배치당 한 번. S#2에서 배운 것.
prior = prior_for(model_id)              # 1층: 평활된 스칼라
try:
    model, tokenizer = load_once(CHECKPOINT)
    try:
        signals = encode_batch(problems, model, tokenizer)
        scores = prior + weight * signals    # 2층: 보정
    finally:
        release()
except Exception:
    scores = [prior] * len(problems)     # 2층 실패 → 1층으로 폴백
return [bool(s >= threshold) for s in scores]
