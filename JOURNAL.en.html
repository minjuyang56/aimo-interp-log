Insert — label recipe, reverse-engineered

Two layers.

Layer 1 — prior. For a known model_id, its smoothed base rate; otherwise the global mean. As S#6 showed, the raw ratio must never be used directly.

Layer 2 — problem signal. Encode the problem with the proxy model to measure how much it leans on surface pattern. Use that to correct layer 1. 

# solutions/layered/solution.py — keep the contract thin
from layered.inference import predict

def are_robust(model_id: str, problems: list[str]) -> list[bool]:
    return predict(model_id, problems)
# layered/inference.py — one model load per batch. The S#2 lesson.
prior = prior_for(model_id)              # layer 1: smoothed scalar
try:
    model, tokenizer = load_once(CHECKPOINT)
    try:
        signals = encode_batch(problems, model, tokenizer)
        scores = prior + weight * signals    # layer 2: correction
    finally:
        release()
except Exception:
    scores = [prior] * len(problems)     # layer 2 failed → fall back to layer 1
return [bool(s >= threshold) for s in scores]

Run it locally. With no model present, layer 2 fails. Layer 1 survives. That is the entire point of the design — when layer 2 dies it returns layer 1's answer instead of raising.

  1. layered/inference.py — return type A numpy comparison can leak np.bool_. The grader tests type(x) is bool, so the whole batch goes invalid. most common failure

  4. layered/inference.py — layer 2 failure path If a model load failure propagates, it takes layer 1 down with it. uncertainty-profiling saved 27/28 with exactly this fallback. core of the design
  5. ZIP layout · determinism Is solution.py at the root? Same input twice, same output? build script + greedy fixed
  6. Docker Was it run in the Dockerfile.competition image, not just the local venv? Skipping this burns a submission. required
