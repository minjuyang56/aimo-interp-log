## 2. 라벨 절차 (주최측 규칙 그대로)

| 단계 | 내용 | 근거 |
|---|---|---|
| ① 선별 | 모델별로 **원본을 k회 샘플**(T=0.6, top_p=0.95) → `base_acc`. **미완주는 오답**으로 센다 | 개정 #37: "완주한 것만 분모" 로 하면 완주가 이미 정답을 골라내 43문제 중 42개가 1.0 이 됐다 |
| ② 채택 | `base_acc ≥ 0.5` 만 변형 단계로. 1.0 도 포함(변형에서 떨어지면 잡힌다) | 개정 #37-1. 실측 채택률 **63%** |
| ③ 변형 | 공식 유형 **rename · typos · distract** + 우리 **상수 변형 v2**(지수·첨자 제외) 각 1개 → N=4~6 | 공식 유형이 라벨 정의와 같고, 상수 변형은 주최측 확인(섭동=풀이 보존·상수만 변경)과 일치 |
| ④ 라벨 | `max_drop = base_acc − min(var_acc)` → **≤0.10 robust · ≥0.25 spurious · 사이 제외** | train-main-v2 에서 역추정한 주최측 임계값 그대로 |
| ⑤ 기록 | 라벨마다 **원인 분해**(오답 n_wrong vs 미완주 n_unfin) 저장 | 개정 #37-2: 미완주를 오답으로 세면 '변형이 길이만 늘려 상한에 걸린' 가짜 spurious 가 섞인다 |

**이 설계의 결정적 이점**: 라벨이 **(모델, 문제) 단위**로 생기므로 `train-main-v2` 에서 0건이던
**모델 간 라벨 차이가 처음으로 생긴다.** H21 에서 계산 불가였던 '모델 간 분리력' 을 드디어 측정할 수 있다.

## 3. 비용 (`analysis/labelgen_plan.py`, 실측 기반)

가정: **150 tok/s**(실측 144.7~287.7 중 낮은 쪽) · 샘플당 **3,500 토큰**(실측 2,773 + level 5 보정) ·
채택률 63%(실측) · 중간대역 제외 30% · **Kaggle 잔여 약 110 GPU-시간**(주 30h × 3.7주).
로컬 GPU 는 4bit 생성 10 tok/s 라 **생성에 쓸 수 없다**(하루 0.86M 토큰) — 프로브 forward 전용.

| 시나리오 | 선별 | 변형 | 합계 | 채택 문제 | (모델,문제) 행 | 라벨 | 예산 내 |
|---|---|---|---|---|---|---|---|
| M=100 · 4모델 · N4 · k4 | 10.4h | 26.1h | **36.5h** | 63 | 252 | **176** | O |
| **M=200 · 4모델 · N4 · k4** | 20.7h | 52.3h | **73.0h** | 126 | 504 | **353** | O ← 권장 |
| M=200 · 2모델 · N4 · k4 | 10.4h | 26.1h | 36.5h | 126 | 252 | 176 | O |
| M=400 · 2모델 · N4 · k4 | 20.7h | 52.3h | 73.0h | 252 | 504 | 353 | O |
| M=400 · 4모델 · N4 · k4 | 41.5h | 104.5h | 146.0h | 252 | 1008 | 706 | **X** |

**권장: M=200 · 4모델 · N=4 · k=4 → 라벨 약 353개(현재 33개의 10.7배), 73 GPU-시간.**
4모델을 유지하는 이유는 모델 간 라벨 차이가 이 계획의 핵심 산출물이기 때문이다(2모델이면 쌍이 1개뿐).

## 4. 학습

| 항목 | 설계 |
|---|---|
| 주 모델 | **모델별 선형 프로브** — 문제 텍스트 **forward 1회**의 hidden state(문제 토큰 평균 풀링), 층은 폴드 내부 CV 로 선택 |
| 보조 | 위 프로브 + 기존 지표(h21c drop K=4 · 즉답 logprob · 엔트로피)를 피처로 추가한 버전 |
| 검증 | **문제 단위 분할**(GroupKFold, 같은 문제가 train/val 에 동시에 들어가지 않게) |
| 외부 테스트 | **공식 `train-main-v2` 33문제** — 학습에 절대 쓰지 않는다 |
| 새로 가능해지는 검정 | **모델 간 분리력**: 같은 문제에서 robust 모델의 점수가 spurious 모델보다 높은 쌍의 비율. H21 에서는 쌍이 0개라 계산 불가였다 |
| 클래스 불균형 | **클래스 가중치**(`class_weight="balanced"`) 또는 균형 샘플링을 쓴다. 생성 라벨은 robust 로 쏠리는 경향이 있고(v1 은 98:2), 검증셋은 균형이므로 쏠린 학습은 바로 손해다 |
| 평가지표 | **balanced accuracy 와 AUC 를 둘 다** 보고한다. AUC 는 순위만 보고 균형에 둔감하고, balanced accuracy 는 실제 판정(bool 벡터)에 대응한다 — 하나만 보면 한쪽을 놓친다 |
| 금지 | 모델별 임계값 튜닝(규칙) · 리더보드 점수로 설계 변경 |

주최측이 원하는 것은 **내부 신호**다(README · 8/3 Discord). 프로브는 그 요구에 정면으로 맞고, 생성이 없어 비용도 거의 0 이다.

## 7. 분업과 자동화 (지휘 #71) — **실측으로 정정됨 (10/6)**

### 로컬 GPU 는 라벨 생성에 쓸 수 없다 (계측 결과)

| max_new | 가능 배치(VRAM) | 합산 tok/s | M=200·k4 선별 소요 |
|---|---|---|---|
| 256 | 61 | 164.7 | 4.7h |
| 1,024 | 25 | 67.5 | 11.5h |
| 4,096 | 7 | 18.9 | 41.2h |
| **8,192 (실제 조건)** | **4** | **10.8** | **72.0h** |

실측(`scratchpad/bench_local.py`): 시퀀스당 **2.7 tok/s 가 배치 1~32 에서 불변** → 배치는 공짜다
(1시퀀스 2.8 · 4시퀀스 11.1 · 8시퀀스 21.3 · 16시퀀스 43.5 · **32시퀀스 87.3 tok/s**).
그런데 KV 가용이 8 GB − 가중치 3 GB − 여유 0.8 GB = **4.2 GB = 34,406 토큰 칸**뿐이라,
max_new 8,192 에서는 배치가 **4** 로 묶여 11 tok/s 가 된다. 짧은 생성에서만 빠르다.

→ **정정**: 앞서 쓴 "로컬이 Kaggle 5.2 GPU-h 를 아낀다" 는 **틀렸다**. 로컬은 라벨 생성에서 제외한다.

| 자원 | 담당(정정) | 근거 |
|---|---|---|
| **로컬 GPU** | **forward 전용**: 프로브 hidden state 추출 · h21 계열 지표(즉답 8토큰·drop·엔트로피) | 짧은 생성·forward 는 배치가 커서 빠르다(배치 61까지 165 tok/s) |
| **Kaggle(vLLM)** | Skywork · DeepSeek · Olmo 전 단계 — **실측 255.7 tok/s**(가정 150 보다 70% 빠름) | vLLM 연속 배칭 |
| **Qwen3.5-4B** | **라벨 생성 제외**(quota 남으면 추가) | vLLM 이 아키텍처를 못 열고, HF 폴백은 Kaggle 에서도 배치가 KV 에 묶여 18h+ |

### 비용 재계산 (255.7 tok/s 실측 반영)
3모델 · M=200 · N=4 · k=4 → 선별 15.6h + 변형 30.7h ≈ **46h** (잔여 110 GPU-h 안). 라벨 약 265개.
Qwen3.5 를 뺀 대가는 **모델 간 분리력 쌍이 3모델 조합으로 줄어드는 것**이고, 쌍은 여전히 3개라 측정은 된다.

### 자동화
`experiments/kaggle/watch_pilot.sh` — 파일럿 COMPLETE 감시 → `analysis/labelgen_pilot_eval.py` **종료코드 판정**
→ 통과 시 3모델 순차 push(슬롯 대기 · 20분 뒤 상태 확인 · ERROR 면 중단). push 전 파서·외부 심볼 점검은 `push()` 안.
1차 파일럿에서 이 가드가 **판정 불가(rc=3)에 push 를 막아** 잘못된 데이터로 수십 시간을 태우지 않았다.

### 1차 파일럿에서 고친 버그
`gold` 는 int, inline 된 `solve_common.extract_answer` 는 str → `"42" == 42` 가 항상 False →
20문제 전부 base_acc 0.0. **비교를 추출기 구현에 의존시키지 않도록** `same_answer()` 를 넣었다(단위 테스트 8종).
부수 관측: max_new 6,144 에서 **11/20 문제가 한 샘플도 완주하지 못했다** → 2차 파일럿은 8,192 로 올렸다.
